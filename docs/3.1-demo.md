# 3.1 第一次提交演示说明

本页只说明 `Chinese can fly` 的 3.1 第一阶段实现怎样检查和演示。需求原文仍以
[`teams/Chinese_can_fly.md`](../teams/Chinese_can_fly.md) 为唯一依据。

## 这次已经接通的流程

1. 玩家在标题页选择开始游戏时，程序生成一个新的 `runId`。
2. 每关 6 秒倒计时结束后开始累计 active play duration；关卡结束后停止累计。
3. 下一关沿用同一个 `runId` 和同一个 `RunSession`，所以记录代表整次游戏，而不是单独一关。
4. 游戏因生命用完或七关全部完成而结束时，程序生成一条 `RunRecord`。
5. 内存仓库按 `runId` 去重；重复的完成事件不会产生第二条记录。
6. 控制台和 `log` 文件输出 run ID、score、enemies defeated、active duration 和 completion time。

当前原游戏没有暂停功能，因此本阶段能够排除的是每关开始前的倒计时和关卡结束后的等待。
计时器采用可重复开始/停止的分段设计；以后增加暂停功能时，只需在暂停和恢复事件中停止、
重新开始分段即可。

## 一键自动检查

在本仓库根目录打开 PowerShell，运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test-records.ps1
```

成功时最后一行应类似：

```text
RecordsSmokeTest passed: 36 checks.
```

这组检查覆盖：字段校验、相同 `runId` 去重、相同分数但不同 `runId` 可并存、只读列表、
多段计时、重复 `start`/`stop`、重复 `finish` 和完整输出字段。

## 手动演示

1. 按项目原来的方式启动游戏。
2. 在标题页选择开始，完成游戏或让生命归零。
3. 打开仓库根目录的 `log` 文件，搜索 `Completed run recorded`。
4. 确认紧随其后的五个字段都有值。
5. 再玩一局，确认新的 `Run ID` 与上一局不同。

示例格式如下，具体数值每局都会不同：

```text
Completed run recorded:
Run ID: 03ab45de-...
Score: 800
Enemies defeated: 15
Active duration: 12000 ms (12.000 s)
Completion time: 1790000000000
```
